# Схема основных Python-модулей генерации табулатуры

```text
[Модуль определения пайплайна и worker-runtime]
      ├── [Модуль предобработки аудио]
      ├── [Модуль разделения дорожек]
      │      └── подшаг: определение наличия гитары
      ├── [Модуль ритмического анализа]
      │      ├── beat/downbeat tracking
      │      ├── темп
      │      └── onset grid по аудио
      ├── [Модуль транскрипции гитары]
      │      └── подшаг: разметка ролей нот
      ├── [Модуль распознавания аккордов]
      ├── [Модуль распознавания боя]
      ├── [Модуль квантования]
      ├── [Модуль эргономики аппликатуры]
      ├── [Модуль сборки и валидации]
      └── [Модуль экспорта табулатуры]
```

**Ключевые технологии:**
- **Celery + Redis/RabbitMQ** — асинхронная очередь задач и пулы воркеров: GPU-воркеры для разделения и транскрипции, CPU-воркеры для ритмического анализа, аккордов, боя и аппликатуры.
- **Demucs `htdemucs_6s`** — 6-стемовая модель разделения микса с отдельными дорожками для гитары и фортепиано поверх стандартных `vocals`, `drums`, `bass`, `other`.
- **Basic Pitch (Spotify)** — лёгкая полифоническая аудио-в-MIDI транскрипция с сохранением velocity и **pitch bend**, что критично для последующего распознавания техник `b` и `h/p`.
- **Librosa / Madmom** — beat/downbeat tracking, определение темп и музыкального размера. Madmom испольТемпзует рекуррентную сеть для битов и динамическую байесовскую сеть для тактов.
- **`music21`** — представление табулатуры через `FretNote` и `FretBoard`, а также интеграция алгоритма Витерби для поиска эргономичной аппликатуры.
- **WhisperX** — ASR с word-level timestamps через VAD и forced phoneme alignment; точность привязки слов к аудио достигает ±10–30 мс.
- **BTC (Bidirectional Transformer for Chord Recognition)** — опциональное уточнение аккордовой сетки на основе self-attention; не входит в обязательный MVP из-за лицензии и сложности.
- **TART** — опциональный фреймворк для распознавания гитарных приёмов (`hammer-on`, `pull-off`, `bend`, `slide`); использует временной CNN-BiLSTM-классификатор для разметки девяти техник.
- **AlphaTab** — рендеринг табулатуры в браузере; поддерживает **MusicXML** (базовая/экспериментальная поддержка), собственный текстовый формат **alphaTex** и файлы Guitar Pro 3–7.

# Основные модули

## 1. Модуль Python-воркеров

**Краткое описание.** Регистрирует Celery-задачи (по одной на каждый pipeline-модуль), определяет DAG пайплайна и маршрутизацию задач по очередям. Сам является worker-runtime: Celery-воркеры исполняют зарегистрированные задачи. Не является сервисом управления — управление job’ами остаётся в Go.

**Вход.** Сообщение очереди от Go: `job_id`, тип пайплайна, ключи S3, пресет.

**Что происходит.**
- Go ставит только входную задачу `preprocess` с `job_id` и ключами S3.
- Celery по цепочке `chain`/`group` запускает следующие задачи: `demucs` → `group(rhythm, transcription)` → `group(chords, strums)` → `chain(quantize, fingering, assemble, export)`.
- Каждая задача маршрутизируется в свою очередь согласно конфигурации (`task_routes`): Demucs → `gpu_separation`, Basic Pitch → `gpu_transcription`, ритмический анализ → `cpu_rhythm`, остальное → `cpu_music`.
- Воркер занят только во время выполнения своей задачи; между задачами он свободен и берёт следующую из своей очереди.
- Каждая задача публикует прогресс в Redis/gRPC, пишет артефакты в S3 и БД, обновляет статус job.
    
- Retry-политики и таймауты настраиваются per-task: Demucs — длинный таймаут, лёгкие задачи — короткий с retry.
    

**Выход.** Результаты задач в S3 и БД; обновления статуса job; событие завершения пайплайна.

**Технологии.** Celery + Redis/RabbitMQ; `chain`/`group`/`chord` для DAG; `task_routes` для маршрутизации; Flower для мониторинга; отдельные worker-пулы на каждую очередь.

## 2. Модуль предобработки аудио

**Краткое описание.** Скачивание (для URL), нормализация и приведение аудио к единому формату.

**Вход.** Исходный аудиофайл из S3 или YouTube-URL; параметры нормализации.

**Что происходит.** Для URL скачивает аудио через `yt-dlp`. Конвертирует в WAV 44.1 кГц, 16 бит, stereo через FFmpeg. Выполняет RMS-нормализацию через Librosa. Проверяет целостность и длительность. Записывает нормализованный WAV в S3.

**Выход.** Нормализованный WAV в S3; длительность и метаданные.

**Технологии.** `yt-dlp`, FFmpeg, Librosa (RMS-нормализация).

## 3. Модуль разделения дорожек

**Краткое описание.** Разделение микса на стемы с выделением гитарного стема. Включает подшаг определения наличия гитары.

**Вход.** Нормализованный WAV; пороги чувствительности.

**Что происходит.** Применяет 6-стемовую модель Demucs (`htdemucs_6s`): `vocals`, `drums`, `bass`, `guitar`, `piano`, `other`. После разделения выполняет подшаг проверки наличия гитары: анализирует энергию и спектральные признаки `guitar.wav`, сравнивает с порогом. Если гитары нет — пайплайн останавливается с `NO_GUITAR_DETECTED` (перспективная ветка аранжировки описана в  [[Модули генерации табулатуры#3. Модуль аранжировки для песен без гитары]]).

**Выход.** Стемы `vocals`, `drums`, `bass`, `guitar` в S3; флаг наличия гитары и confidence; при отсутствии — код ошибки.

**Технологии.** Demucs v4 `htdemucs_6s`; эвристика по энергии/спектру.

## 4. Модуль ритмического анализа

**Краткое описание.** Вычисляет общую ритмическую сетку для аккордов, боя и квантования: beat/downbeat, темп, размер, onset grid.

**Вход.** Нормализованный WAV или `drums.wav` для beat/downbeat; `guitar.wav` для onset grid; параметры сетки.

**Что происходит.** Выполняет beat tracking и downbeat detection, определяет темп и музыкальный размер. Строит единую beat grid и downbeat grid. Отдельно выполняет onset detection по аудио гитарного стема (спектральная энергия) и формирует `onset_grid` для распознавания боя. Результаты кладутся в общий контекст выполнения: `beat_grid`, `downbeats`, `bpm`, `time_signature`, `onset_grid`.

**Выход.** `beat_grid`, `downbeats`, `bpm`, `time_signature`, `onset_grid`; артефакт в `tab_analysis_artifacts`.

**Технологии.** Librosa / Madmom (beat/downbeat tracking); onset detection по спектральной энергии.

## 5. Модуль транскрипции гитары

**Краткое описание.** Преобразование гитарного аудио в MIDI с сохранением силы удара и таймкодов. Включает подшаг разметки ролей нот.

**Вход.** `guitar.wav`.

**Что происходит.** Запускает polyphonic transcription (Basic Pitch), извлекает ноты, высоту, начало/конец, velocity. Сохраняет MIDI. Затем выполняет подшаг разметки ролей: одиночные ноты в верхнем регистре — `melody`, одновременные 3+ ноты — `chord`, низкие одиночные — `bass`, короткие украшения — `ornament`. Разметка выполняется эвристиками по MIDI, без отдельного аудио-анализа.

**Выход.** `guitar.mid` с нотами, velocity, таймкодами и полем `role`.

**Технологии.** Basic Pitch (Spotify); эвристики на основе music21 (плотность, регистр, длительность).

## 6. Модуль распознавания аккордов

**Краткое описание.** Распознаёт аккордовую сетку. Основной путь — эвристика по нотам с ролью `chord`; BTC (Bidirectional Transformer for Chord Recognition) — опциональное уточнение.

**Вход.** MIDI с нотами и ролями; `bass.wav`; общий `beat_grid` и `downbeats` из Модуля ритмического анализа.

**Что происходит.** Группирует ноты с ролью `chord` по временным окнам, привязанным к beat grid. Определяет символ аккорда по входящим нотам (например, C-E-G → C, A-C-E → Am), учитывает басовую ноту из `bass.wav` для обращений. Сглаживает кратковременные ошибки. При включённой опции применяет BTC к гармоническим стемам и сравнивает с эвристикой. BTC не является обязательным для MVP из-за лицензии и сложности.

**Выход.** Аккордовая сетка: последовательность аккордов с временными границами, долями и confidence; `chords.json`.

**Технологии.** Эвристика по нотам и басовой линии; опционально BTC.

## 7. Модуль распознавания боя и ритмического рисунка

**Краткое описание.** Распознаёт удары вниз/вверх, приглушения и акценты. Основной путь — правила по MIDI; CRNN — опция.

**Вход.** `guitar.wav`; MIDI с нотами; `onset_grid` и `beat_grid` из Модуля ритмического анализа.

**Что происходит.** Сопоставляет onset-события из аудио с нотами MIDI. По умолчанию применяет правила: направление удара — по порядку струн в MIDI (басовые раньше тонких → вниз; наоборот → вверх); `muted` — по низкой velocity и короткой длительности; акцент — по velocity относительно соседних нот. Формирует паттерн боя по тактам. CRNN для joint strumming/chord transcription остаётся опцией для сложных случаев, не обязательным модулем MVP.

**Выход.** События боя: доля, направление, приглушение, акцент, confidence; `strumming.json`.

**Технологии.** Правила по MIDI; onset detection; опционально CRNN.

## 8. Модуль квантования

**Краткое описание.** Привязка нот, аккордов и событий боя к общей ритмической сетке.

**Вход.** MIDI после транскрипции; аккордовая сетка; события боя; `beat_grid`, `bpm`, `time_signature` из Модуля ритмического анализа; пресет сетки.

**Что происходит.** Читает общий beat grid и округляет начало и длительность нот, границы аккордов и позиции ударов к выбранной сетке (1/4, 1/8, 1/16). Сохраняет исходные таймкоды для отладки. Обеспечивает единую временную ось для всех слоёв.

**Выход.** Квантованный MIDI; квантованные аккордовая сетка и события боя; общая beat grid.

**Технологии.** Алгоритмы округления к сетке.

## 9. Модуль эргономики аппликатуры

**Краткое описание.** Распределяет ноты по струнам и ладам с учётом удобства игры и выбранного пользователем пользовательских настройках.

**Вход.** Квантованный MIDI с ролями нот; пресет пользователя.

**Что происходит.** Строит граф возможных позиций каждой ноты на грифе с учётом строя и каподастра. Из пресета вычисляет веса штрафов и жёсткие ограничения для функции стоимости: за растяжку пальцев, баррэ, резкие переходы, смену позиции, неудобные комбинации. Конкретные веса и ограничения зависят от выбранного уровня сложности и пользовательских предпочтений, которые могут переопределять дефолты уровня. Применяет алгоритм Витерби для выбора последовательности позиций с минимальной суммарной стоимостью при заданных ограничениях. Для аккордовых нот проверяет одновременную зажимаемость и соответствие выбранному уровню. Если при заданном уровне аппликатура невозможна, повышает сложность с предупреждением либо помечает такт как проблемный. Использует `music21` для представления табулатуры.

**Выход.** Табулатура: для каждой ноты — струна, лад, позиция; проверенная на эргономичность в рамках выбранного уровня сложности; предупреждения о тактах, где пришлось повысить сложность или где аппликатура не найдена.

**Технологии.** `music21` (FretNote, FretBoard); алгоритм Витерби с настраиваемой функцией стоимости; пресеты сложности в виде наборов весов и ограничений; эвристики штрафов, параметризованные пресетом.

## 10. Модуль сборки и валидации табулатуры

**Краткое описание.** Сливает ноты, аккорды и бой в единый документ и проверяет его целостность.

**Вход.** Табулатура с аппликатурой; аккордовая сетка; события боя; роли нот; метаданные (темп, размер, строй). Опционально — техники и слова, если включены отдельные вертикали.

**Что происходит.** Синхронизирует слои по общей временной сетке. Для каждого такта формирует аккорд(ы), паттерн боя, ноты со струнами/ладами/ролями. Разрешает конфликты: если нота помечена как `chord`, но аккорд не распознан, восстанавливает символ по нотам; если бой не распознан, оставляет нотный слой без паттерна. Проставляет confidence. Формирует единый объект с `schema_version`. Затем выполняет подшаг валидации: проверяет обязательные поля, корректность струн/ладов, согласованность временных границ, отсутствие пересечений нот на одной струне, валидность символов аккордов, наличие `schema_version`. Без `schema_version` результат невалиден. Возвращает документ и список ошибок/warnings.

**Выход.** Валидированный документ табулатуры (внутренний JSON); список ошибок и warnings.

**Технологии.** Python-структуры данных; JSON Schema; проверки музыкальной целостности.

## 11. Модуль экспорта табулатуры

**Краткое описание.** Упаковывает результат в форматы для плеера и хранения.

**Вход.** Валидированный документ табулатуры; эталонный MIDI.

**Что происходит.** Генерирует `tab.json` (внутренний контракт плеера) и `tab.musicxml`. Для AlphaTab проверяет, что плеер потребляет MusicXML или AlphaTex; при необходимости генерирует AlphaTex. Сохраняет отдельные артефакты `chords.json`, `strumming.json`, опционально `lyrics.json`. Записывает всё в S3, создаёт записи в `tabs` и `tab_analysis_artifacts`. Сохраняет эталонный MIDI для отладки.

**Выход.** `tab.json`, `tab.musicxml`, `chords.json`, `strumming.json`, опционально `lyrics.json` в S3; записи в БД.

**Технологии.** music21 (MusicXML export); AlphaTab-совместимые форматы (MusicXML, AlphaTex); JSON.

# Бонусные модули

## 1. Модуль распознавания гитарных приёмов

**Краткое описание.** Распознаёт техники `h`, `p`, `b`, `/`, `x` и привязывает их к нотам. Основной путь — правила по MIDI и pitch bend; TART — опционально для спорных случаев.

**Вход.** `guitar.wav`; MIDI с нотами и таймкодами; pitch bend от Basic Pitch; опционально ручная правка в UI.

**Что происходит.** По умолчанию применяет правила: hammer-on/pull-off — легатные переходы без повторной атаки; bend — плавное изменение высоты по pitch bend; slide — скольжение частоты; приглушённые струны (`x`) — шумовые onsets с низкой гармонической энергией. При низком confidence техника не проставляется. Transformer (TART) рассматривается как опция для сложных случаев, не обязателен для MVP.

**Выход.** Список техник с привязкой к нотам/переходам и confidence; добавляется в табулатуру отдельной задачей.

**Технологии.** Правила по MIDI и pitch bend; спектральные эвристики; опционально TART.

## 2 Модуль распознавания текста песни

**Краткое описание.** Распознаёт текст песни и привязывает слова к временной сетке. Вынесен в отдельную вертикаль, не входит в основной пайплайн генерации табулатуры.

**Вход.** `vocals.wav`; опционально текст песни от пользователя.

**Что происходит.** Запускает ASR (WhisperX) с word-level timestamps через VAD и forced alignment. Определяет язык. Если пользователь передал текст, выполняет forced alignment исходного текста к аудио. Привязывает слова к строкам и, где возможно, к долям/тактам. Отмечает низкую уверенность. Результат сохраняется отдельным артефактом и может быть опционально добавлен в табулатуру, но основной пайплайн от него не зависит.

**Выход.** Текст, язык, слова/строки с `start_ms`/`end_ms` и confidence; `lyrics.json`.

**Технологии.** WhisperX (Whisper + VAD + forced alignment); опционально stable-ts.

## 3. Модуль аранжировки для песен без гитары

**Краткое описание.** Генерирует гитарную партию «с нуля», если в аудио нет гитары.

**Вход.** Аккордовая сетка, вокальная мелодия (если доступна), `drums.wav`, `bass.wav`; пресет стиля.

**Что происходит.** Выбирает шаблон боя/перебора («шестёрка», «восьмёрка», fingerstyle) на основе ритма барабанов и гармонии. Распределяет мелодию на  и бас. Проверяет одновременную зажимаемость аккордов. При необходимости использует генеративную модель (Google Magenta / лёгкий трансформер) для вариаций. Сформированная партия проходит эргономику, сборку и экспорт.

**Выход.** Гитарная табулатура, сгенерированная без исходного гитарного аудио.

**Технологии.** Шаблоны боя/перебора; Google Magenta; лёгкий трансформер; проверка аппликатуры.
