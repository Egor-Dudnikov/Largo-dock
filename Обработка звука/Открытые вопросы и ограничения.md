# 1. Аудио и предобработка

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Расстроенная гитара** | Если гитара не настроена, Basic Pitch и анализ высоты будут ошибаться систематически | Добавить коррекцию строя в предобработку или явно предупреждать пользователя |
| **Шум и качество записи** | Записи с телефона, комнатный фон, дыхание, скрип струн снижают точность транскрипции и тренировки | Определить минимальные требования к записи; добавить проверку SNR и предупреждение |
| **Длинные треки** | Demucs и Basic Pitch на треках >5–7 минут требуют много GPU-памяти и времени | Ввести лимит длительности; продумать чанкинг или понижение качества для длинных треков |
| **Форматы и кодек** | Не все .m4a / .flac корректно конвертируются; некоторые URL-источники отдают нестандартные потоки | Проверить FFmpeg-пайплайн на реальных файлах; добавить коды ошибок |
| **URL-источники** | yt-dlp может ломаться при изменениях на стороне YouTube/SoundCloud | Нужен мониторинг ошибок скачивания; предусмотреть fallback и понятные сообщения |
| **RMS-нормализация** | Может «поднять» шум в тихих записях | Проверить, не ухудшает ли нормализация транскрипцию на тихих записях |

# 2. ML-модели и лицензии

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Demucs — NC-лицензия** | Веса htdemucs_6s — CC-BY-NC; коммерческое использование запрещено | Для коммерции: получить лицензию у Meta, обучить свою модель или найти альтернативу с разрешительной лицензией |
| **BTC — NC-лицензия** | Веса BTC-Chord — CC-BY-NC-SA; коммерческое использование запрещено | Для MVP — эвристика по нотам; для коммерции — своя модель или замена |
| **MERT — NC-лицензия** | Не подходит для коммерческого использования | Не включать в коммерческий пайплайн |
| **Basic Pitch — Apache 2.0** | Лицензия разрешительная, но качество на акустике с шумом ограничено | Дообучение или постобработка; см. раздел 4 |
| **CRNN для боя** | Опциональная модель; лицензия и качество не проверены | Уточнить лицензию и необходимость; для MVP — правила по MIDI |
| **TART** | Не модель с одной лицензией, а исследовательский фреймворк | Использовать как референс, не как готовый артефакт |
| **WhisperX** | Тяжёлая модель; качество ASR на вокале с музыкой может падать | Проверить на реальных треках; для MVP — опционально |
| **Google Magenta** | CC-BY 4.0, требует attribution | Указать авторство в UI, если используется |

# 3. Транскрипция гитары

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Полифония и обертоны** | Basic Pitch может принять обертон за отдельную ноту или пропустить ноту в аккорде | Постобработка: фильтр по уверенности, ограничение диапазона, сглаживание |
| **Затухание струны** | Длинное затухание акустики накладывает ноты друг на друга | Проверить, как Basic Pitch справляется; при необходимости — сегментация |
| **Быстрые пассажи** | На высоких скоростях ноты сливаются | Проверить на реальных записях; возможно, ограничить сложность в пресетах |
| **Разметка ролей** | Эвристики (melody/chord/bass/ornament) могут ошибаться на границах | Определить пороги; предусмотреть ручную правку в UI |
| **Pitch bend от Basic Pitch** | Не все версии и форматы MIDI сохраняют pitch bend одинаково | Проверить, что pitch bend доходит до модуля техник |
| **Дообучение** | Требует размеченного датасета; полное обучение может не воспроизвести результаты статьи | Сначала препроцессинг и постобработка; fine-tuning — после сбора данных |

# 4. Аккорды и бой

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Эвристика аккордов** | Определение по нотам может ошибаться на обращениях, надстройках, нестандартных аккордах | Определить поддерживаемый набор аккордов; остальное — ручная правка |
| **Базовая нота** | Без bass.wav обращения определяются хуже | Использовать басовый стем; при его отсутствии — предупреждать |
| **Направление удара** | Правило «басовые раньше тонких → вниз» работает не всегда (например, при игре пальцами) | Проверить на реальных записях; предусмотреть ручную правку |
| **Muted / акцент** | Определение по velocity и длительности может ошибаться | Уточнить пороги; для MVP — эвристика |
| **Паттерны боя** | Библиотека шаблонов («шестёрка», «восьмёрка») не покрывает все рисунки | Определить минимальный набор; остальное — не классифицировать |
| **CRNN для боя** | Лицензия и качество не проверены; тяжелее правил | Оставить опцией; для MVP — правила по MIDI |

# 5. Техники (h/p/b/slide/x)

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Определение по MIDI** | Hammer-on/pull-off и slide по правилам дают кандидатов, но не гарантируют точность | Низкий confidence не проставлять; ручная правка в UI |
| **Bend** | Зависит от pitch bend Basic Pitch; не все бенды фиксируются | Проверить на реальных записях; при необходимости — анализ аудио |
| **Dead note (x)** | В MIDI её может не быть вовсе; по аудио — ненадёжно | Для MVP — только ручная правка |
| **TART** | Требует размеченных данных и обучения; не готов «из коробки» | Оставить опцией на будущее |

# 6. Аппликатура

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Веса Viterbi** | Качество аппликатуры зависит от весов штрафов; их нужно подбирать | Определить дефолты для пресетов «Новичок» и «Опытный»; проверить на реальных табах |
| **Невозможная аппликатура** | Для некоторых нот при заданном уровне аппликатура может не найтись | Повышать сложность с предупреждением или помечать такт проблемным |
| **Аккорды с барре** | На акустике барре на высоких ладах физически тяжело | Штрафовать; проверять одновременную зажимаемость |
| **Каподастр и строй** | Не все комбинации строя и каподастра корректно отрабатываются | Проверить на Standard E, Drop D, DADGAD; определить поддерживаемые комбинации |
| **Субъективность** | «Удобно» для одного гитариста неудобно для другого | Дать ручную правку в UI; собирать обратную связь |

# 7. Сборка и валидация

# 8. Тренировка: фронтенд

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Калибровка задержки** | Без неё оценка несправедлива: пользователь стабильно «опаздывает» на 50–100 мс | Обязательная калибровка перед сессией; ручной ползунок в опытном режиме |
| **Производительность на мобильных** | CREPE full может не тянуть real-time; батарея греется | Fallback CREPE → YIN; режим «только запись» для длинных сессий |
| **Совместимость WebGPU** | Не везде доступен | Fallback на WASM |
| **SharedArrayBuffer** | Требует COOP/COEP-заголовков | Настроить Go-сервер; проверить в разных браузерах |
| **Точность YIN vs CREPE** | YIN быстрее, но менее точен на полифонии | Определить, достаточно ли YIN для одной гитары; иначе — CREPE-tiny |
| **Разные устройства** | Микрофоны и задержки сильно различаются | Калибровка под устройство; тесты на разных телефонах и ноутбуках |

# 10. Инфраструктура и очередь

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **Единый beat grid** | Все модули должны читать один и тот же beat_grid | Явно передавать его через контекст выполнения; запретить пересчёт |
| **Состояние между задачами** | Артефакты не передаются через очередь | Читать/писать через S3; в сообщении — только job_id, ключи и пресет |
| **Retry и таймауты** | Demucs долгий, лёгкие задачи короткие | Настроить per-task: длинный таймаут для Demucs, короткий с retry для cpu_music |
| **Head-of-line blocking** | Demucs и Basic Pitch в разных GPU-очередях | Подтвердить на реальной нагрузке; при необходимости — разделить пулы |
| **Согласованность статусов** | Go и Python пишут в разные хранилища | Определить идемпотентность обновлений; избегать «зависших» статусов |
| **Мониторинг очередей** | Нужно видеть длину очередей, retry, ошибки | Flower + Prometheus/Grafana; алерты на задержки |
| **Стоимость GPU** | Demucs и Basic Pitch на GPU дороги | Оценить стоимость на реальной нагрузке; рассмотреть батчинг и кэширование |

# 11. Безопасность и приватность

| **Вопрос / ограничение** | **Суть** | **Что нужно решить** |
|----|----|----|
| **SSRF через URL** | Пользователь может передать вредоносную ссылку | Валидировать домены в Go; не позволять Python скачивать произвольные URL |
| **TTL временных файлов** | Аудио и стемы занимают много места | Настроить lifecycle policy в S3 |
| **Приватность тренировки** | Аудио пользователя может быть чувствительным | По умолчанию не отправлять аудио; только события |
| **Доступ к артефактам** | Presigned URL могут утечь | TTL, привязка к пользователю, запрет на публичные бакеты |

# 14. Что проверить в первую очередь

1. **Точность Basic Pitch на реальных акустических записях** — базовая метрика, от которой зависит всё.

2. **Качество Demucs htdemucs_6s на акустике** — насколько чист guitar.wav.

3. **Работа правил боя и направления удара** — на нескольких паттернах.

4. **Калибровка задержки на разных устройствах** — fairness тренировки.

5. **Производительность CREPE/YIN в браузере** — real-time или нет.

6. **Совместимость MusicXML с AlphaTab** — не потеряются ли слои.
